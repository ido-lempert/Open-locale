# 0061 - TMX export (translation memory portability)

PLAN Phase 1 names TMX export alongside translation memory. This slice adds
it, export-only.

## Scope

- `GET /projects/:id/tm/:locale/tmx` returns a TMX 1.4 document: one `<tu>`
  per memory entry pairing the base-locale source with the target-locale
  text, escaped, sorted by source text. Entries with empty targets are
  excluded (memory never stores them, and the export filters again).
- Export-only: there is no TMX import. The header fields (creationtool,
  segtype, adminlang, srclang, datatype) describe only what we emit; no
  external TMX consumer acceptance is claimed.
- Guards mirror TM suggestions: project membership (cross-team 404) and the
  locale must be a non-base project locale (400 otherwise).
- Web: an "Export TM (TMX)" button in the editor IO toolbar downloads
  `<slug>-<locale>.tmx` for the selected import/export locale, with a notice
  stating the export-only nature.

## Boundaries verified

- tm-test: header + known pair, markup/quote escaping, per-locale isolation,
  base-locale 400, cross-team 404, and exclusion of keys with no
  target-locale memory.
- e2e-visual: real button click, blob captured, 1.4 header and at least one
  non-empty en->he pair asserted; screenshot taken.
- No CLI format: TMX is memory portability, not a translations interchange
  format, so it is deliberately not in the push/pull format list.
