# 0058 - RESX (.NET XML resources) import/export

RESX joins the format list as the tenth format: import through
POST /import/:locale (body field `resx`), export through
GET /export/:locale/resx, plus bundle support (entry extension .resx),
the CLI (push detects .resx, pull --format resx) and the editor
import/export pickers.

## Subset, stated plainly

Flat string resources only: one `<root>`, `<data name="..." xml:space="preserve">`
rows with a `<value>` child. Everything else is rejected, not approximated:

- `<data>` rows with `type` or `mimetype` attributes (typed/binary resources),
- `<metadata>` sections and `<assembly>` aliases,
- inner markup inside `<value>`,
- duplicate or missing names, missing `<value>`, missing `<root>`.

Two explicit losses: `<resheader>` rows and `<comment>` children are ignored
on import, so neither survives a round trip. Export emits the four resheader
entries .NET tools conventionally write (resmimetype/version/reader/writer)
plus `xml:space="preserve"` on every data row; that is a structural claim
about what we emit, not validated acceptance by any specific external
consumer, which this repo has not tested against.

Security note: the reader is a lexical scan, not a general XML parser, and it
fails closed on anything that would need one: a document with a DOCTYPE or
ENTITY declaration is rejected whole (no resolution is possible, and nothing
is silently left literal), and an entity reference beyond the five predefined
XML ones - including numeric character references - rejects the entry with a
400 and unchanged data. Roots carrying a namespace (prefix form or `xmlns`
attribute) are rejected. Whitespace inside `<value>` is preserved verbatim on
import regardless of `xml:space`.

## Boundaries verified

- Import runs through the shared per-locale path: membership, per-locale
  grants, task locks (member leg: locked key skipped, unlocked lands) and
  branch scope (`?branch=` on both import and export) behave exactly as for
  the other nine formats. No new write path was added.
- Preview: `?dryRun=true` parses RESX through the same dispatch, writes
  nothing.
- A typed-resource rejection is whole-file 400 with keys byte-identical
  before/after; duplicate names and metadata sections are 400.
- Bundle: the .resx entry byte-equals the single-locale export; import-bundle
  routes it through the same importer. Store-only zip subset unchanged.
- Round trip: export -> import reports all values unchanged.

RESX stays a one-way-street subset in one respect: keys are flat names, and
RESX has no hierarchy to lose - but comments and resheaders do not come back.
