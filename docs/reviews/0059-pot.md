# 0059 - POT (gettext template)

Eleventh interchange format: POT, the gettext template form. POT is not a
translation delivery format: it carries msgids with intentionally empty
msgstr values so translators start from a template.

## Scope

- Export: `GET /projects/:id/export/:locale/pot` (also `?branch=`) emits the
  project's keys as msgids with every `msgstr ""` - translated keys are
  blanked too; a template carries no translations. This is a structural
  claim about what we emit, not validated acceptance by any external gettext
  consumer.
- Import: a `pot` body field parses through the same PO parser. Empty msgstr
  values create keys and fill translations that do not exist yet, but a blank
  template entry NEVER overwrites an existing translation: the writing
  statement checks the stored value inside the same transaction and skips
  (counted as unchanged), so importing a template over a translated project
  cannot erase wording. Plurals (msgid_plural/msgstr[n]) and contexts
  (msgctxt) are rejected with a 400 and unchanged data, exactly as for PO.
- CLI: `.pot` push detection and `--format pot`. Web: picker option,
  extension detection, accept lists, download `.pot` extension and
  `text/plain` type, and a `pot` payload field (import and preview share
  the same builder).
- Zip bundles: `.pot` is part of the per-locale bundle maps (export-all and
  import-bundle), one template per locale.

## Boundaries verified

- Import runs through the shared per-locale path: membership, per-locale
  grants (member leg: outside-grant locale denied 403), and branch scope on
  both import and export.
- Export blanking is asserted directly: a key with a real translation in the
  locale appears in the POT as `msgstr ""`.
- Import preservation is asserted at the boundary: a blank entry for a
  translated key leaves the translation in place and counts unchanged, while
  a blank entry for a new key lands as an empty translation.
- The roundtrip leg imports a full POT export into a fresh empty branch and
  asserts main is untouched.
- Browser click-through: real `.pot` upload (notice + grid row, screenshot)
  and POT export blob captured and asserted for the template header and
  empty msgstr values.
