# 0027 - OTA publications (private, authenticated)

## What shipped
- `OtaPublication` model: immutable bundle per (project, branch, version), payload maps
  locale -> { key: value }, cascade with project and branch. Versions increment per branch.
- POST `/projects/:id/ota/publish` {branch?} - admin AND session principal (SessionOnlyGuard,
  same rule as branch management): a leaked CI/SDK token cannot publish releases.
- GET `/projects/:id/ota` - publication metadata (branch, version, locales, counts).
- GET `/projects/:id/ota/latest?locale=&branch=` and `/projects/:id/ota/:version/:locale?branch=` -
  bundle pull. Weak ETag `W/"v<version>-<locale>"` with `Cache-Control: private, no-cache`;
  If-None-Match returns 304. Specific versions are immutable; latest moves.
- Retention: latest 25 publications per (project, branch); older ones pruned on publish.
- Settings UI: OTA publications panel (list, branch picker, Publish bundle, summary notice).
- Activity: `ota.published` recorded per publish.

## Explicit limits and auth rules
- Pull is AUTHENTICATED ONLY: session JWT or read-scope API token (the intended SDK path).
  Unauthenticated requests get 401; non-members 403/404. There is no public/CDN endpoint and
  none was deployed - public rollout needs separate authority.
- Publish is admin + session only (API tokens 403 even with write scope).
- Bundles include every existing translation row for the branch, including empty values and
  any review status (no status filtering) - consumers do their own fallback; documented so the
  semantics are a choice, not an omission.
- Bundle payload carries translations only (no comments/tasks/TM/screenshots).
- No delta/incremental format, no SDK client, no CDN caching headers beyond revalidation.
